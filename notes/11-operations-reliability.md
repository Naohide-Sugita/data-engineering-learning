## 11-1. Cloud Monitoring

### Dataflowの継続監視
- Dataflowの遅延、スループット、エラーなどのメトリクスを継続監視できる
- アラートポリシーで閾値超過や異常時に通知できる
- 「Dataflowを常時監視 + 性能低下やエラー時に通知」→ Cloud Monitoring

## 11-2. Cloud Logging

- ログ、エラーメッセージ、例外などを確認して原因調査に利用する
- Monitoring：状態・メトリクス・アラート
- Logging：詳細ログ・原因調査

## 11-3. 高可用性 / 災害復旧

### Cloud SQLのHA構成
- 同一リージョン内の別ゾーンにスタンバイを配置する
- ゾーン障害時に自動フェイルオーバーする
- 「Cloud SQL + ゾーン障害 + 自動フェイルオーバー」→ HA構成

## 11-4. バックアップ / リカバリ

### BigQueryスナップショットとタイムトラベル
- スナップショット：テーブルの特定時点の状態を保存する読み取り専用テーブル
- タイムトラベル：直近の変更履歴から過去状態を参照・復元する
- 誤削除・誤更新からの復旧に利用できる

## 11-5. レプリケーション / フェイルオーバー

### Cloud SQLのクロスリージョンDR
- 同一リージョンHA：ゾーン障害に備える
- クロスリージョンリードレプリカ：リージョン障害に備える
- クロスリージョン複製は非同期で、プライマリ性能への影響を抑えやすい
- 「リージョン障害 + RPO重視 + プライマリ性能維持」→ クロスリージョンレプリカ

## 11-8. エラー / クォータのトラブルシューティング

### Dataflowジョブ失敗
- まずDataflowジョブ詳細を確認する
- ジョブログ・ワーカーログからエラーや例外を確認する
- パイプライングラフから失敗ステップを特定できる
- 「失敗済みDataflowジョブを調査」→ ジョブログ / ワーカーログ

### 断続的なDataflow障害
- Cloud Loggingでエラー・例外を確認する
- Cloud MonitoringでCPU・メモリ・遅延などのメトリクスを確認する
- 「断続的な障害」→ Logging + Monitoringで切り分ける

### BigQuery Scheduled Queryの失敗
- Scheduled queriesのRun historyで失敗した実行を確認する
- エラー詳細やジョブIDを確認できる
- 「Scheduled Query失敗を迅速に確認」→ Run history

## 11-9. コスト最適化

### BigQueryリザベーション
- クエリ処理に使うコンピューティング容量を予約・割り当てる
- 部門ごとにプロジェクトやリザベーションを分けると、リソース・コストを分離しやすい
- 「部門別にBigQueryコストを管理・予測」→ 部門別プロジェクト + リザベーション
